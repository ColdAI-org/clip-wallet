## What changed in code for the deploy

- `services/media-proxy`: worker renamed to `clip-media-proxy`, `workers_dev: true`. **IPFS gateway moved off
  ipfs.io**: ipfs.io and dweb.link stopped serving content over plain HTTP in September 2026 (they now answer 429
  with "switching to a service worker gateway only"; https://gatewaychanges.ipfs.io/). Filebase's public path
  gateway serves any CID and is the new default. It is a shared, rate-limited public gateway: use a dedicated
  gateway (Filebase, Pinata, or your own Kubo) before real traffic, by changing `IPFS_GATEWAY`.
- `services/backup`: worker renamed to `clip-backup`, real D1/R2 names and id, `workers_dev: true`.
  - With no email provider, `POST /v1/auth/start` now refuses **before** touching D1 (previously it wrote a
    rate-limit row and a link row, then deleted the link).
  - `GET /v1/health` returns `{"ok":true,"emailSignIn":<bool>}`.
  - New `ResendEmailSender`; the entry point uses it only when both the `RESEND_API_KEY` secret and the
    `EMAIL_FROM` var are set. Otherwise it stays in the "not configured" state.
  - Three new tests (24 total).

## Redeploy

```
cd services/media-proxy && npx wrangler deploy
cd services/backup && npx wrangler d1 migrations apply clip-backup-db --remote && npx wrangler deploy
```

`wrangler deploy` keeps secrets. Vars come from `wrangler.jsonc`, so change them there, not in the dashboard.

## Rotate

- **`EMAIL_PEPPER`.** Accounts are keyed by `HMAC(EMAIL_PEPPER, email)`, so a new pepper orphans every existing
  account and its backups (users sign in again and re-upload; blobs stay undecryptable without their passkey either
  way). Today there are no accounts, so rotating is free:
  `openssl rand -base64 32 | npx wrangler secret put EMAIL_PEPPER`.
  After real users exist, rotate only on suspected compromise, and announce it.
- **`RESEND_API_KEY`** (once set): create a new key in Resend, `npx wrangler secret put RESEND_API_KEY` and paste
  it at the prompt, then delete the old key in Resend.
- **Rate-limit namespace**: change `namespace_id` in `services/media-proxy/wrangler.jsonc` and redeploy.

## Tear down

Point both `clip.config.ts` files away from these URLs first (or the testnet builds will show the features and
fail), then:

```
cd services/media-proxy && npx wrangler delete clip-media-proxy
cd services/backup && npx wrangler delete clip-backup
npx wrangler r2 bucket delete clip-backup-blobs     # must be empty first
npx wrangler d1 delete clip-backup-db
```

Deleting the D1 database and R2 bucket is permanent. Export first if there is anything worth keeping
(`npx wrangler d1 export clip-backup-db --remote --output backup.sql`).

## Turn on email sign-in (owner)

The Worker needs three things: an API key, a sender on a verified domain, and the page the link opens.

1. In Resend (https://resend.com), add and verify a sending domain (Domains → Add domain; add the SPF/DKIM
   records it lists to that domain's DNS). Then create an API key with "Sending access", limited to that domain.
2. Set the secret (wrangler prompts for the value; nothing lands in the shell history):

   ```
   cd services/backup
   npx wrangler secret put RESEND_API_KEY
   ```

3. In `services/backup/wrangler.jsonc` set:
   - `EMAIL_FROM`: e.g. `"Clip Wallet <backup@your-verified-domain>"`.
   - `APP_URL`: the page the emailed link opens; the wallet reads `#/backup/sign-in?token=…` from the fragment.
     Today it is the placeholder `https://wallet.example/backup`. For the extension this is the extension
     page, e.g. `chrome-extension://<extension id>/tab.html`, and the extension id only stays stable if the
     manifest has a `key` (or once it is published in the Chrome Web Store).
   - `ALLOWED_ORIGINS`: only needed for callers that are subject to CORS (web pages). The extension calls the
     backup from its background with host permission, which CORS doesn't apply to.

4. Deploy and check:

   ```
   npx wrangler deploy
   curl -s https://clip-backup.doyoka-platform.workers.dev/v1/health    # {"ok":true,"emailSignIn":true}
   ```

To switch it off again: `npx wrangler secret delete RESEND_API_KEY` (health goes back to `emailSignIn: false`).

## Google / Apple sign-in

**Not implemented.** The backup Worker only knows email links; there is no OAuth/OpenID code path, so no secret
or command turns Google or Apple sign-in on today. Setting `GOOGLE_*`/`APPLE_*` secrets would do nothing. What the
owner will need once the code exists (the sign-in stream adds it, then this section gets the exact commands):

- Google: an OAuth 2.0 client in Google Cloud Console (APIs & Services → Credentials), with the redirect URI the
  Worker will expose, plus the OAuth consent screen filled in.
- Apple: an Apple Developer Program membership, a Services ID with "Sign in with Apple" enabled and the return
  URL registered, and a Sign in with Apple private key (`.p8`) with its Key ID and Team ID.

Those values would go in as Worker secrets through `npx wrangler secret put <NAME>` (prompted, never on the
command line), and the client ids into `wrangler.jsonc` vars.
